# Preregistration E8: the machine-checked composition pilot (2026-09-09)

Written and frozen by hash before any model call. Registered publicly on OSF before the run; the registration id and the FREEZE-E8.txt hashes are recorded beside this file. Author: Chris Gascon. The harness, the task family, the hand-written rules and the system prompt were written by the author's AI assistant, which also wrote the two organs under test. This is disclosed here because the draft plan asked for someone else to write the monolithic baseline and nobody else was available on the day.

## Question

Does wiring the two organs together buy anything that the same two organs, present but unwired, do not, against a conventional baseline given the same call budget? The registered report (osf.io/dah6v) asks this with human raters and is unfunded. This pilot asks the cheapest machine-checkable version.

## The wire

The kit's memory organ (DurableLearningOrgan over a JsonFileStore) injects a stored lesson ahead of a prompt when the lesson's cue appears in the prompt, case-insensitive. The kit's repair loop (runConstraintRepair) generates, runs the checker, and on a failure re-prompts with the specific violation, up to three retries (budget four generations). Today nothing the repair loop learns reaches the store. The wire under test: when a task's first attempt fails the checker, the harness writes one lesson for that task's constraint class into the store. The memory organ recalls it on every later task of the same class, including on repair attempts, because the repair prompt carries the task text and so the cue.

Lesson mechanics, exactly as coded in e8.mjs: one lesson per class, id `e8-<class>`, replaced on each new first-attempt failure of that class. Its content is the template

    <Class description> tasks have failed the check <n> time(s) so far. Latest failure: <lesson text>. Satisfy the <class description> rule before finishing.

where n counts that class's first-attempt failures so far in the repetition. The lesson text is the checker's measurement and the requirement, with no words quoted from the response. The checkers for the forbidden-letter and lowercase classes quote example words in the violation they feed the repair loop and strip them from the lesson text. No lesson carries topic words or response text; a mechanical leakage check runs afterwards and is reported.

## Arms

Six arms. Every arm and repetition runs in a fresh operating-system process. Haiku 4.5 through Bedrock (us.anthropic.claude-haiku-4-5-20251001-v1:0), temperature 0.7, maxTokens 400, ceiling of four generations per task. The first attempt of every arm appends the kit's first-shot suffix ("Output only the response, nothing else."). No first draft is shared between arms.

1. Base. One generation per task (the kit's repair loop with enabled false, which is byte-identical to a single call).
2. Repair only. The E6c stack: the repair loop around the memory-wrapped base, with an empty store that nothing writes to. Both organs present, no wire; the memory organ never fires. This is what the kit does today.
3. Integrated. The same stack with the wire. The store starts empty in every repetition and fills only from the repair loop's own first-attempt failures.
4. Supplied rules. The same stack with the store pre-loaded before the run with the eight hand-written rules below, one per class, and nothing written during the run. The analogue of E6's supplied-key control: the ceiling the wire is trying to reach.
5. Monolithic prompt. The bare base with the system prompt below on every call, one generation per task. The prompt-engineering answer.
6. Monolithic resampling. Arm 5 with verifier-selected best-of-four: up to four independent generations, stopping at the first that passes the checker.

## Task family

Eight constraint classes, fifteen prompts each, 120 prompts, each on its own topic from a list of 120 topics written for this pilot (none in the kit's T39 or T20 sets or in IFEval; none contains a cue). Generated by e8-tasks.mjs from seed 20260910 and frozen as tasks-e8.json. Templates, each containing its class cue:

| Class | Cue | Template | Parameters |
|---|---|---|---|
| wordcount | Word count | Write a short piece about {topic}. Word count: between {lo} and {lo+4} words. | lo in {25, 30, 35, 40, 45, 50, 60} |
| sentences | sentences | Write about {topic} in exactly {n} sentences. | n in {2, 3, 4, 5} |
| noletter | without using the letter | Write a short paragraph about {topic} without using the letter "{L}" anywhere in your response. | L in {b, c, d, f, g, k, l, m, p, v, w, y}, never a letter of the topic |
| commas | comma | Write a short paragraph about {topic} that uses exactly {n} comma(s) / that uses no commas at all. | n in {0, 1, 2, 3} |
| lowercase | lowercase | Write a short paragraph about {topic} entirely in lowercase: no capital letters anywhere. | none |
| bullets | bullet | Give {n} facts about {topic} as exactly {n} bullet lines, each starting with "- ", with no other text before or after them. | n in {3, 4, 5, 6} |
| ending | End your response with | Write a short paragraph about {topic}. End your response with the exact phrase "{phrase}" and put nothing after it. | five fixed phrases |
| frequency | Use the word | Write a short paragraph about {topic}. Use the word "{w}" exactly {n} times. | eight fixed words, n in {2, 3, 4} |

Checkers (e8-tasks.mjs, pure functions of the response text). Pass is the checker's verdict on the arm's final response.

- A word is a maximal run of non-whitespace characters.
- A sentence is a maximal run ending in one or more of the three terminal marks (period, exclamation mark, question mark). A trailing run with a letter and no terminal mark counts as one sentence.
- The forbidden letter is counted case-insensitively.
- Commas are the count of the comma character.
- Lowercase means no character in A to Z anywhere.
- Bullet lines means every non-empty line starts with "- " and there are exactly n non-empty lines.
- The ending phrase must be the final characters after trimming trailing whitespace.
- Word frequency counts whole-word, case-insensitive matches.

Guards run before freezing (selfCheck in e8-tasks.mjs): each prompt contains its own cue and no other class's cue; no topic, the first-shot suffix or any supplied rule contains another class's cue; 120 distinct topics; each class has 7 or 8 prompts in the second half.

## Sequence

One fixed order for every arm and repetition. For each class, a seeded shuffle of its fifteen prompts puts the first 7 (even class index) or 8 (odd) into the first half and the rest into the second. Each half is then shuffled with the same seeded generator. Positions 1 to 60 are the first half, 61 to 120 the second, so every class recurs and appears 7 or 8 times in each half. Three repetitions of the whole sequence; repetitions differ only by sampling. The harness runs the six arms of a repetition as separate child processes, three at a time; nothing is shared between them.

## Supplied rules (arm 4) and system prompt (arms 5 and 6)

The eight rules, verbatim from e8-tasks.mjs:

- Word count tasks: count every word before you finish and stay inside the requested window. Earlier answers ran long; when unsure, write fewer words and count again.
- Sentence count tasks: count the sentences before you finish, one per terminal mark, and match the requested number exactly. Earlier answers added an extra sentence.
- Forbidden letter tasks: scan every word for the banned letter before you finish and replace any word that contains it, including the topic itself if needed.
- Comma count tasks: count the commas before you finish and match the requested number exactly; rephrase to add or remove commas rather than adding text.
- Lowercase tasks: no capital letters anywhere, including the first word, the pronoun i, names and abbreviations.
- Bullet line tasks: output exactly the requested number of lines, each starting with "- ", with no heading, introduction or closing line.
- Ending phrase tasks: the exact phrase must be the final characters of the response, with no punctuation, sign-off or blank text after it.
- Word frequency tasks: count the exact occurrences of the required word before you finish, including plurals and capitalized forms, and match the number exactly.

The system prompt is the line "Follow every formatting rule in the request exactly. Rules that apply to every task:" followed by the eight rules as bullet lines. Arm 4 receives the same eight rules through the memory organ, one at a time by cue; arm 5 receives all eight on every call through the system prompt. That is the intended contrast.

## Outcomes

Primary: integrated minus repair only, pass rate over positions 61 to 120 (60 prompts, after the store has met every class several times). Per prompt, pass averaged over the three repetitions per arm, paired difference per prompt, percentile bootstrap over prompts (2,000 resamples, seed 12345, alpha 0.05, the itemBootstrap in bedrock-e8.mjs, which also returns a two-sided bootstrap p-value). Kill rule: an interval that includes zero means the wire bought nothing measurable on this task family, and the report says so.

Secondary, one Benjamini-Hochberg family at q = 0.05, all on positions 61 to 120, same estimator. Seven comparisons:

- integrated minus supplied rules, how much of the ceiling the wire recovers;
- repair only, integrated and supplied rules, each minus monolithic prompt;
- repair only, integrated and supplied rules, each minus monolithic resampling.

Descriptive, all reported without inference:

- the same comparisons on positions 1 to 60 and on all positions;
- pass rate by arm and class;
- the learning curve, pass rate by block of twenty positions, for base, repair only, integrated and supplied rules;
- calls and tokens per arm;
- every lesson written by the integrated arm with its position, and the final store of each repetition;
- the leakage check: a lesson that contains any of the 120 topic strings, or that does not match the lesson template exactly, is a flag, and the count is reported.

## Predictions

Integrated above repair only on the second half, by a few points, carried by the classes whose lesson text names a fixable quantity (word count, sentence count, comma count, word frequency, ending phrase), and level on forbidden letters and lowercase. Supplied rules at or above integrated. Monolithic prompt near supplied rules on first-attempt pass rate, since it is handed every rule too, and below the repair arms on final pass rate. Monolithic resampling near repair only, as in E2 and E5. If repair only already passes nearly everything on the second half, the family is too easy for the question and the report says so.

## Void conditions and disclosure

A run is void and rerun in full, with the reason disclosed, in three cases: any arm's Bedrock error count exceeds one percent of its calls; a checker is found wrong for its stated definition during the run; a child process fails. Anything else that goes wrong is reported, not repaired. Nothing from the scripted-fake smoke test (smoke/, run before freezing to exercise the pipeline) is data.
