# Preregistration E9: the lesson-design follow-up to E8 (2026-09-10)

Written and frozen by hash before any model call, and registered publicly on OSF before the run. The registration id and the frozen SHA-256 values are recorded beside this file in REGISTRATION-E9.txt and FREEZE-E9.txt. Author: Chris Gascon. The author's AI assistant wrote the two organs under test, the harness, the task family, the lesson templates and the rules; the plan says so because nobody else was available to write them.

## Question

E8 (osf.io/qc3db, DOI 10.17605/OSF.IO/QC3DB) wired the repair loop's first-attempt failures into the memory store and found no gain and a loss in one class. Its exploratory note offered two explanations. First, the lesson text was misleading: it carried the latest failure's parameter, a specific banned letter, which was the wrong letter on most later prompts. Second, any block injected ahead of a repair prompt dilutes the specific feedback the loop depends on, whatever the block says. E9 runs three lesson designs side by side so the two explanations make opposite predictions.

## The three wires

All three follow E8's mechanics: when a task's first attempt fails the checker, the harness writes one lesson to the store, and the memory organ recalls lessons whose cue appears in a later prompt, including on repair attempts, because the repair prompt carries the task text. They differ only in what is stored and under which cue. The templates below are verbatim from e9.mjs. In them, N is that lesson's running failure count, and the lesson text is the checker's measurement and requirement with no words quoted from the response.

Wire A, the E8 template. One lesson per class, cue the class cue, replaced on every new failure of the class:

    <Class description> tasks have failed the check N time(s) so far. Latest failure: <lesson text>. Satisfy the <class description> rule before finishing.

Wire B, parameter-free. One lesson per class, cue the class cue, replaced on every new failure. The summary is computed from the misses so far (measured minus target for the four counted classes; the count of the banned letter for the fifth) and names a direction and a mean size, never a target, letter or word:

    <Class description> tasks have failed the check N time(s) so far: <summary>. Check this task's own <class description> requirement before finishing.

    where <summary> is one of: the answers ran over by X <units> on average; the answers fell short by X <units> on average; the answers missed in both directions, by X <units> on average; the banned letter appeared X times on average.

Wire C, parameter-keyed. One lesson per class and parameter. The cue is the parameter phrase exactly as it appears in the prompt (for example, exactly 40 words; exactly 5 sentences; the letter "m"; exactly 3 commas; "river" exactly 4 times), so the lesson is recalled only on prompts with the same parameter. The content is the Wire A template, whose specific is then the right one.

## Arms

Six arms. Haiku 4.5 through Bedrock (us.anthropic.claude-haiku-4-5-20251001-v1:0), temperature 0.7, maxTokens 400, at most four generations per task. Every arm and repetition runs in a fresh operating-system process. The kit's first-shot suffix ("Output only the response, nothing else.") is appended to every first attempt. No draft is shared between arms.

1. Base. One generation per task, through the kit's repair loop with enabled false, which is byte-identical to a single call.
2. Repair only. The E8 stack: the repair loop (maxRetries 3) around the memory-wrapped base, with an empty store that nothing writes to. Both organs present, no wire.
3. Wire A. The stack with the E8 wire. The replication arm.
4. Wire B. The stack with the parameter-free wire.
5. Wire C. The stack with the parameter-keyed wire.
6. Supplied rules. The stack with the five E8 hand-written rules for these classes pre-loaded in the store and nothing written during the run. The ceiling, as in E8.

The monolithic arms of E8 are not repeated. E8 placed them on this kind of family: the organ arms beat the system prompt by 18 to 21 points and were level with best-of-four resampling. E9's budget goes to the wire designs.

## Task family

Five classes, twenty-four prompts each, 120 prompts, each on its own topic from the E8 pool of 120 topics. Six parameter values per class, each used exactly four times, so that every parameter recurs and a keyed lesson has something to recall. Generated by e9-tasks.mjs from seed 20260911 and frozen as tasks-e9.json.

| Class | Cue | Template | Parameters |
|---|---|---|---|
| wordcount | Word count | Write about {topic}. Word count: exactly {N} words. | N in {20, 30, 40, 50, 60, 75} |
| sentences | sentences | Write about {topic} in exactly {n} sentences. | n in {3, 4, 5, 6, 7, 8} |
| noletter | without using the letter | Write a short paragraph about {topic} without using the letter "{L}" anywhere in your response. | L in {c, d, l, m, p, s}; the topic never contains L |
| commas | comma | Write a short paragraph about {topic} that uses exactly {n} comma(s), or that uses no commas at all. | n in {0, 1, 2, 3, 4, 5} |
| frequency | Use the word | Write a short paragraph about {topic}. Use the word "{w}" exactly {n} times. | w in {river, window, ladder}, n in {3, 5} |

Checkers are the E8 checkers, with an exact word count in place of the window. Pass is the checker's verdict on the arm's final response.

- A word is a maximal run of non-whitespace characters.
- A sentence is a maximal run ending in one or more terminal marks (period, exclamation mark, question mark). A trailing run with a letter and no terminal mark counts as one sentence.
- The forbidden letter is counted case-insensitively.
- Commas are the count of the comma character.
- Word frequency counts whole-word, case-insensitive matches.

Guards run before freezing (selfCheck in e9-tasks.mjs): every prompt contains its class cue and its parameter cue; no prompt contains another class's cue; each parameter cue matches only prompts of its own class and parameter; no topic contains a cue; no forbidden-letter topic contains its letter; every topic is used once; each parameter value is used four times; each class has twelve prompts in each half.

## Sequence

One fixed order for every arm and repetition. For each class, a seeded shuffle of its twenty-four prompts puts twelve into each half. Each half is then shuffled with the same seeded generator. Positions 1 to 60 are where the stores fill; positions 61 to 120 are where the lessons are measured. Three repetitions of the whole sequence; repetitions differ only by sampling. The harness runs the six arms of a repetition as separate child processes, three at a time; nothing is shared between them.

## Outcomes

Primary: Wire B minus repair only, final pass rate over positions 61 to 120 (60 prompts). Per prompt, pass averaged over the three repetitions per arm; paired difference per prompt; percentile bootstrap over prompts (2,000 resamples, seed 12345, alpha 0.05; the itemBootstrap in bedrock-e9.mjs, which also returns a two-sided bootstrap p-value). Its sign separates the two explanations. If the misleading parameter was the problem, Wire B sits above repair only. If injection itself dilutes the repair prompt, Wire B sits at or below it. Kill rule: an interval that includes zero means no parameter-free wire earns its place on this family either, and the report says so.

Secondary, one Benjamini-Hochberg family at q = 0.05, same positions and estimator, six comparisons:

- Wire A minus repair only, whether E8's loss replicates.
- Wire C minus repair only.
- Wire B minus Wire A, and Wire C minus Wire A, whether removing or keying the parameter recovers the loss.
- Wire B minus supplied rules, and Wire C minus supplied rules, the distance to the ceiling.

Mechanism outcomes, reported with bootstrap intervals but outside the family: the first-attempt pass rate of each arm on positions 61 to 120, its difference from repair only, and the recovery rate, the share of first-attempt failures that the retries recovered, per arm. E8 saw the wire raise first attempts while lowering final passes; these two numbers say whether that repeats.

Descriptive, all reported without inference: the same comparisons on positions 1 to 60 and on all positions; pass rate by arm and class, all positions and second half; the learning curve by block of twenty; calls and tokens per arm; every lesson written by each wired arm with its position and the final store of each repetition; the number of prompts on which Wire C recalled anything; and the leakage check, a flag for any lesson that contains one of the 120 topic strings or does not match its arm's template.

## Predictions

If the misleading parameter explains E8: Wire A at or below repair only in the forbidden-letter class and level elsewhere; Wire B and Wire C above repair only by a few points, mostly in word count, sentence count and comma count, where the direction of a miss is informative; both above Wire A. If dilution explains E8: all three wires at or below repair only on final pass, while at or above it on first attempts. Supplied rules at or above every wire. The family is expected to have room: repair only between 70 and 90 percent overall. If repair only passes more than 95 percent of the second half, the family was too easy again and the report says so.

## Void conditions and disclosure

A run is void and rerun in full, with the reason disclosed, in three cases: any arm's Bedrock error count exceeds one percent of its calls; a checker is found wrong for its stated definition during the run; a child process fails. Anything else that goes wrong is reported, not repaired. The scripted-fake smoke test (smoke/) ran before the freeze to exercise the pipeline; nothing from it is data. The harness imports the kit from the local build at commit 61fd546, whose code is identical to the commit the book pins (3d20393); the commits between are documentation only.
